# Telegram-бот билетов с оплатой через СБП

Проект продает билеты через Telegram-бота: пользователь выбирает тариф, оплачивает заказ, а после подтверждения оплаты получает QR-код билета.

В проекте есть:

- тестовый режим без списания денег;
- боевая заготовка оплаты через СБП в YooKassa;
- пул QR-кодов по каждому тарифу;
- генерация уникального QR, если пул закончился;
- бесплатные QR-коды для ручной раздачи;
- экспорт базы билетов для проверяющего;
- Android-приложение проверяющего: импорт базы, сканирование, одноразовый проход;
- запуск на Windows через `.bat`-файлы.

## Быстрый тест на Windows

1. Распакуйте проект.
2. Дважды нажмите `START_DEMO_WINDOWS.bat`.
3. Вставьте токен Telegram-бота из BotFather.
4. Откройте бота в Telegram и отправьте `/start`.
5. Выберите тариф.
6. Нажмите `Демо: подтвердить оплату`.

В демо-режиме реальные деньги не списываются.

## Боевой запуск с оплатой СБП

1. Дважды нажмите `START_PRODUCTION_WINDOWS.bat`.
2. Если файла `.env` нет, скрипт создаст его из `.env.example` и откроет в Блокноте.
3. Заполните настройки.
4. Запустите `START_PRODUCTION_WINDOWS.bat` еще раз.

Минимальные боевые настройки в `.env`:

```env
BOT_TOKEN=...
PAYMENT_PROVIDER=yookassa
PUBLIC_BASE_URL=https://your-domain.example
RETURN_URL=https://your-domain.example/return
WEBHOOK_SECRET=long-random-string
YOOKASSA_SHOP_ID=...
YOOKASSA_SECRET_KEY=...
ADMIN_USER_IDS=123456789
```

Чтобы узнать свой Telegram user ID, запустите бота и отправьте ему `/id`. Потом впишите ID в `ADMIN_USER_IDS`.

Webhook для YooKassa:

```text
https://your-domain.example/payments/yookassa/long-random-string
```

Его нужно добавить в YooKassa для событий:

- `payment.succeeded`
- `payment.canceled`

Подробная инструкция: `docs/PAYMENTS_YOOKASSA_SBP.md`.

## Админ-команды бота

Админом считается пользователь, чей Telegram user ID указан в `.env`:

```env
ADMIN_USER_IDS=123456789
```

Команды:

- `/id` - показать свой Telegram user ID.
- `/admin` - справка по админ-командам.
- `/export` - выгрузить JSON-базу билетов для приложения проверяющего.
- `/free light 10` - создать 10 бесплатных QR-кодов тарифа `light`.
- `/free basic 5` - создать 5 бесплатных QR-кодов тарифа `basic`.
- `/free luxury 3` - создать 3 бесплатных QR-кода тарифа `luxury`.

После команды `/free` нужно снова выполнить `/export`, чтобы бесплатные QR попали в базу для телефона.

## Проверка QR на входе

Порядок работы:

1. После завершения продаж админ отправляет боту `/export`.
2. Бот присылает JSON-файл базы билетов.
3. Проверяющий открывает Android-приложение.
4. Нажимает `Импорт базы JSON`.
5. Выбирает файл экспорта.
6. Нажимает `Сканировать QR`.

Каждый QR проходит только один раз на этом телефоне. Повторное сканирование покажет `УЖЕ ИСПОЛЬЗОВАН`.

Важно: если на входе несколько телефонов, у каждого телефона своя локальная отметка прохода. Для нескольких входов нужна либо синхронизация через сервер, либо распределение разных потоков/зон между проверяющими.

Инструкция по приложению: `docs/VALIDATOR_APP.md`.

## Тарифы

- Лайт: 600 руб.
- Базовый минимум: 900 руб.
- Роскошный максимум: 2000 руб.

Тарифы и цены лежат в `bot/tariffs.py`.

## QR-коды

Пул заранее подготовленных кодов хранится в `data/qr_pool.json`.

Пример есть в `data/qr_pool.example.json`:

```json
{
  "light": ["LIGHT-001", "LIGHT-002"],
  "basic": ["BASIC-001", "BASIC-002"],
  "luxury": ["LUXURY-001", "LUXURY-002"]
}
```

Если `ALLOW_DYNAMIC_QR=true`, бот сам создаст уникальный QR, когда пул закончится.

## Скрипты

- `START_DEMO_WINDOWS.bat` - самый простой тестовый запуск.
- `START_PRODUCTION_WINDOWS.bat` - боевой запуск после заполнения `.env`.
- `STOP_BOT_WINDOWS.bat` - остановить запущенного бота этого проекта.
- `CHECK_PROJECT_WINDOWS.bat` - проверка проекта.
- `BUILD_VALIDATOR_APK_WINDOWS.bat` - собрать APK приложения проверяющего.
- `MAKE_RELEASE_ZIP_WINDOWS.bat` - собрать чистый zip для передачи.

## Как собрать zip для передачи

Запустите:

```text
MAKE_RELEASE_ZIP_WINDOWS.bat
```

Готовый архив появится тут:

```text
.release\qr-ticket-bot-release.zip
```

В архив не попадают секреты и локальные файлы: `.env`, `.venv`, логи, база SQLite, сгенерированные QR, экспорты и локальный `data/qr_pool.json`.

Если перед сборкой был создан `dist\qr-ticket-validator-debug.apk`, APK приложения проверяющего тоже попадет в архив.

## Требования

- Python 3.9 или новее.
- Windows (для `.bat`-скриптов). На Linux/macOS запускайте `python -m bot` напрямую после создания `.env`.

## Структура проекта

- `bot/app.py` - Telegram-бот и HTTP webhook-сервер.
- `bot/config.py` - загрузка настроек из `.env`.
- `bot/payments.py` - тестовый и YooKassa-провайдеры оплаты.
- `bot/database.py` - заказы, база SQLite, резервирование QR.
- `bot/qr_tickets.py` - выдача и генерация QR.
- `bot/tariffs.py` - тарифы и цены.
- `bot/admin_tools.py` - экспорт базы и создание бесплатных QR.
- `scripts/` - PowerShell-скрипты запуска, остановки, сборки релиза.
- `validator_app/` - Android-приложение проверяющего.
- `docs/` - инструкции для передачи, проверки QR и подключения оплаты.
- `data/qr_pool.example.json` - пример пула QR-кодов (скопируйте в `data/qr_pool.json`).
